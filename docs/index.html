The Problem & Story

The Post-Git Pull Paralysis

The Old Way (Friction & Guesses)
  1. 1. You SSH into VPS: cd ~/KeshavSoft/appointment-notifier
  2. 2. You update code: git pull origin main
  3. 3. The Freeze: What was the systemd service name?
  4.   • appointment.service?
  5.   • appointment-notifier.service?
  6.   • appointment.keshavsoft.com.service?
  7. 4. You spend 5 minutes reading /etc/systemd/system/ or restart the entire server causing downtime!
The ubuntu-service Way (Zero Memory)
  1. 1. Stand right in your project folder.
  2. 2. Run: us restart
  3. 3. Instant Context Match:
  4.   • Reads process.cwd()
  5.   • Finds matching WorkingDirectory
  6.   • Executes systemctl restart appointment.keshavsoft.com.service
  7.   • Displays instant post-restart PID, memory, and status!
Unix Separation of Concerns

Singular vs. Plural Architecture

Two complementary tools solving different layers of Linux VPS operations.

Aspect ubuntu-service (Singular) ubuntu-services (Plural)
Core Role The Atomic Operator (Current App) The Fleet Guardian (OS Registry)
Scope Single unit attached to current directory All service units across the entire OS
Key Question "What runs ME right now, and let me restart it." "What is running everywhere, and are any folders broken?"
Short Alias us [restart|logs|name] usv [doctor|dirs|inspect]
Primary Daily Trigger Immediately following git pull System audits, health checks, troubleshooting 502s

Reference Guide

CLI Commands & Flags

us (default)

Inspects the service owning current directory. Shows state, PID, memory, port, and WorkingDirectory health.

us restart

Safely restarts only this service via systemctl and immediately verifies post-restart health.

us logs [-n <count>]

Pulls the last 25 lines (or custom count) of journalctl logs for this specific unit.

us name / us port

Outputs strictly the service unit name or port number, ideal for shell piping and CI scripts.
